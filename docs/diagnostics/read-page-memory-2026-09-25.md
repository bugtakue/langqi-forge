## 问题与设计

12cc封印轨迹中同会话/同文件SHA/同起止行重复读取14次。旧滚动压缩保留最新读取和至多36KB源码首尾快照，中段旧页可以再次消失。因此不能将这些重复调用一律归因于模型无视已经可见的代码。

新增通用 `source_memory.py`：只收集已由read_file/read_files实际返回的完整页面正文，保留原行号或字符游标及SHA，不生成摘要。每会话最多24页、序列化条目合计36,000字节；去重后按最近使用优先，超过则淘汰旧页。失败、只有哈希的兜底、搜索结果和其他工具不能冒充源页。

滚动压缩时，先保留原初始输入/完整规格/新鲜工具观察，再尝试留存至多18,000字节已读页；这部分从原有36,000字节源码快照预算内扣除，不另加上下文预算。每页必须完整放得下，JSON转义后的实际消息也必须满足原上下文上限。新鲜观察不再重复缓存进入当前消息。页按不可信数据引用，`<`转义，不能成为更高优先级指令。

写入成功且changed=true时作废该文件的旧页；每次选择前还通过原路径安全规则和2MB读限重新计算磁盘SHA，抵御绕过工具的变更、删除或越界软链。跨会话不沿用缓存。未保留的页、未读源码及完整文件覆盖仍未知。

范围：本轮仅改变滚动压缩；初始验收审计仍采用原12KB快照与新鲜观察保护，没有承诺任何场合都能保留所有已读页。完整需求、SHA覆写、构建/行为验收和候选晋升门不变。
