# 在长篇写入之前明确防覆盖参数

## 实测触发

正式Pro运行`359dd7e72ca7`的request72连续两次约240秒超时，第三次101.243秒返回；seq538报告输入25,420、输出7,542 Token。紧接着seq540的write_file因缺失expected_sha256被拒，随后又读取源码。7,542是该响应报告的输出用量，不是已核验的文件大小；完整调用参数仍待封印轨迹。没有据此判断全部超时根因或擅自移除防覆盖检查。

检查当前源码：系统提示与参数description已要求已有文件使用最新观察到的SHA，但write_file的JSON Schema只将path/content列为required，expected_sha256在content之后。模型漏填已发生，不能说原说明不存在。

## 最小候选

只调整模型可见的write_file工具合同：required包含path、expected_sha256、content；属性顺序也将哈希放在长代码之前。字段始终为string，只有新文件使用空字符串，已有文件使用最近一次读/写回执的SHA。未增加工具、模型请求或依赖，未改HTTP超时/重试策略、文件写入实现或验收门。

这不是严格输出模式，也不能保证提供商按字段顺序生成或永不遗漏。工具运行时依旧拒绝已有文件的缺失、空值与过期哈希；不自动猜哈希，不从磁盘补填绕过模型的读写前提。新建仍受原路径、规格阅读与写入预算限制。
