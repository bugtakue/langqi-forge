# 通用事务的状态与响应结果分离

## 真实触发

8f/GLM的封印生成轨迹2d8bb92545c0，注册拆分seq149：模型在updateState回调修改会话后返回接口结果对象，通用storage遂把结果对象保存为整份状态。seq229/234的浏览器观察显示登录跳转后及刷新仍为游客。来源和限制见glm-final-generation-2026-09-26.md；未打开评分期应用数据。

原updateState是合法的完整替换API，不能自动判断任意新对象是正常新状态还是错误响应。静默猜测或限制合法状态键都会引入歧义，因此保留其原语义，另提供明确的transactState(mutator)。

## 实现

- 新接口取得fresh draft，在原串行队列内执行mutator；只把draft原子落盘，再返回mutator结果。结果为对象、数值或undefined都不会变成数据库。
- 与旧updateState共享queueWrite，不创建两个互不协调的写队列。抛错或JSON序列化失败不持久化草稿，队列继续接受后续事务。
- 模型提示明确读取用loadState，原位修改和独立响应使用transactState；完整替换才用updateState。验收提醒检查状态/响应分离，仍要求需求行为、浏览器检查与独立回归。
- 不新增业务路由、数据、模型调用或额度，不改当前正式运行，不阻止模型合法替换或删除状态。

## 本地证据与限制

新增中性Node夹具先以缺少transactState导出失败。实现后同一夹具确认旧误用会把数据库变成receipt对象；新接口保留原items、增加新项与计数，只单独返回receipt。再次启动Node读取同一state.json验证持久化，临时写文件没有残留。
