# 浏览器计划的有界多错误反馈

## 真实观察与范围

8f30652/GLM正式运行2d8bb92545c0首批seq111/116因为步骤数组/长度被拒，seq121动作不支持；拆分重试又出现seq219数组/长度与seq224文本断言数量错误。精简stdout未显示原始参数，不猜测实际数组长度、类型或动作值。首批seq129记录21回合、一次真实探针仍未验证、整批未晋升，故不能宣称完成收尾已救回功能。

工具schema已经公开动作枚举、16步和每字段4个断言的限制。当前反馈只报告首个错误，模型必须再次调用才能发现另一错误。本候选只改善拒绝后的反馈，不替模型猜测正确流程，不改变动作/断言上限或验收规则，不热改正式运行。

## 窄实现

- `invalid_plan_diagnostics`复用原`validate_steps`，只在整体计划已经被拒后检查至多16个步骤，收集至多8个错误；每个步骤仍只报告原验证器遇到的第一个错误。
- 返回实际步骤数（不是数组时null）、原限制、动作枚举、实际检查数量及一基步骤号。禁止输出原始计划或任意动作值；错误消息最多300字符。
- 同时解释断言附在动作上，没有独立assert/wait动作；提醒保留需求与断言、不能简单截掉步骤凑上限，未检查步骤仍可能有错。
- 整体仍`ok=false`、`plan_executed=false`，不启动浏览器、不增加browser_probe_calls、不验证当前revision、不晋升、不新增模型调用。已存在的recheck义务与先前已验证流程语义保持。
- 有效计划完全沿用原路径；正确修正后仍须实际浏览器执行和原始预算。预算耗尽/未通过构建等前置拒绝不绕过。

## 验证与限制

中性夹具同时含不支持动作、过多文本断言与外部导航：旧版只给首个error，新增回归先以缺失plan_diagnostics失败；候选返回步骤2/3/4的三个问题且未修改输入、未启动浏览器，完整工具结果仍进入有效哈希链。

新增3项测试覆盖类型/长度区分、1000步输入最多检查16步且最多8错误、回复小于4000字符、不回显非数组输入、修正后真实探针仍是必要条件、原预算耗尽先拒绝。针对性47项：44通过、3既有真实浏览器环境跳过（0.141秒）。完整回归358项，355通过/3既有环境跳过，64.168秒；git diff --check通过。

这是格式纠错协议测试，没有真实模型比较、没有证明省下多少Token，更不证明官方得分提高。候选未封包/未上传，正式GLM仍精确8f30652。
